# TK 发货与旺季备货决策台

这是一个面向 TikTok Shop / FBT 的库存决策工具。系统通过领星 OpenAPI 获取商品、销量、FBT 库存和 FBT 货件数据，按动态日均、库存时间线、旺季覆盖计划和物流渠道时效，生成每周发货建议、下周理论买货缺口和旺季备货采购表。

项目的核心目标不是机械计算“物流时效 × 日均销量”，而是回答三个实际问题：

1. 商品按当前销售速度会不会在下一批货入仓前断货？
2. 本周一共需要发多少货，才能同时覆盖近期销售和旺季累计目标？
3. 这些货应由快递、空派、快船、普船卡派和慢船中的哪些渠道承接？

## 主要功能

- 从领星拉取 TikTok 在售商品、7/14/30 天销量、FBT 库存、FBT 可售和 FBT 在途。
- 拉取 FBT 货件、发货单、物流渠道、跟踪号和预计到货信息。
- 将同店铺内仅末尾相差 `-US` 的 MSKU 合并为一个商品组。
- 计算动态日均、预计断货日、日常近期缺口、旺季累计缺口和下周买货缺口。
- 按最终预计入仓日从早到晚分配物流渠道，自动计算渠道间的桥接量。
- 支持精准船期模式和固定“安全天数 + 发货频率”模式。
- 支持渠道独立启停、时效范围、截单日、开船日、安全天数和频率配置。
- 支持停止收货日约束，来不及入仓的慢渠道自动让位给更早渠道。
- 支持 IBR 到货台账导入、自动对账、人工补充跟踪号和到货日期。
- 支持人工复核本周各渠道数量，并实时更新库存预测曲线。
- 支持在人工复核中新增多次发货节点；人工固定任一批次数量后，其余批次按逐日库存守恒公式自动增减并在必要时新增接力渠道。
- 待复核方案作为草稿保存；已复核和已执行方案才成为首页、库存曲线与 Excel 导出的正式生效数量。
- 首页汇总、商品列表、下周买货测算和 Excel 导出统一读取同一份“正式生效数量”，避免系统建议量与人工复核量口径分裂。
- 支持正常补货、清仓、下架三种产品状态。
- 支持独立的旺季供应商备货采购页面及 Excel 导出。

## 快速启动

建议使用 Python 3.11 或更新版本。

```powershell
python -m pip install -r requirements.txt
$env:LINGXING_APP_ID="你的领星 App ID"
$env:LINGXING_APP_SECRET="你的领星 App Secret"
python run_webapp.py
```

浏览器访问：

```text
http://127.0.0.1:8766/
```

Windows 也可以运行根目录的 `启动TK补货决策台.cmd`。

## 测试

```powershell
python -m pytest webapp/tests APIs/tests
```

## 数据与安全

- 正式运行数据保存在本机 `webapp/data/tk_replenishment.db`，数据库不会提交到 Git。
- 导入和导出的 Excel、历史业务文档以及缓存文件不会提交到 Git。
- GitHub 版本不包含任何真实领星或飞书密钥。
- 新环境必须通过 `LINGXING_APP_ID` 和 `LINGXING_APP_SECRET` 环境变量提供领星凭证。
- 服务默认只监听 `127.0.0.1`，当前版本没有登录权限系统，不应直接暴露到公网。

## 当前业务边界

- 不使用 ROI、MOQ、箱规、本地仓和供应商未到数据。
- 采购备货页当前计算旺季毛需求，不扣 FBT 库存、FBT 在途和历史采购。
- 暂不处理重复采购扣减。
- 断货商品会提示动态日均可能失真，但当前没有逐日断货数据来自动还原损失销量。
- 物流跟踪号优先使用领星返回值；接口缺失时仍需人工维护。
- 自动接力节点只在现有计划发货日及下一复核周期内寻找可行渠道，不会在任意日期中求解理论最晚发货日。
- 同一渠道的多个日期节点在发货建议 Excel 中按渠道合计；批次日期明细以商品详情中的复核节点为准。
- “已执行”暂未自动生成跨周在途台账；货件进入领星/IBR 前，需要维护“已发未同步”并防止下周重复建议。
